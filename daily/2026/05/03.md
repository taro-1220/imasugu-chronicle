## なぜ逸れたか
- snapshot 復元は「restore → 画面表示」の単純なフローに見えたが、実際には save effect / lib store 変更 / browser history の3つが干渉していた
- 05/02 で導入した復元ロジックが想定外の副作用を複数持っていた

## 反省
- snapshot の保存と復元を同じ useEffect 系ロジックに載せると、副作用の実行順序が保証されない
- restore complete フラグを立てる前に他の effect が走ることを防ぐ設計が必要だった
- 「直したら別のバグが出る」連鎖は、初期設計の副作用境界が不明確だったサイン

## 学んだこと
- snapshot 復元は「復元フェーズ中は save を禁止する」ロック機構が必要
- browser history と内部ステップ状態を二重管理すると戻るボタンの挙動が競合する。どちらを正とするか決める必要がある
- ブランクスクリーンは snapshot 不在時のフォールバック表示を最初から用意しておけば防げた
