## 実際にやったこと

- 支払い後に bill と split の state をリセット
- マップの全店舗名ラベルを復元
- マップマーカーのちらつきを安定化・デバッグログを削除
- 保存済みカードの customer 不一致を修正（bill payment）

## 横道に逸れたこと
- `crypto.randomUUID` fallback（`9eb57b3`）— Safari テスト中に UUID 生成が undefined になりクラッシュした
- v2 メニュートランジション非表示（`248ed30`）— v1 ユーザーに v2 の UI が見えてしまっていた

## なぜ逸れたこと
- split storage クリーンアップを確認するため Safari でテストしていると `crypto.randomUUID is not a function` で落ちた
- feature flag で v2 をゲートしているのに、メニューのトランジションアニメーションが v1 でも表示されていた。flag の適用漏れ

## 反省
- `crypto.randomUUID` は `https` または `localhost` でしか使えない（Secure Context 制約）。HTTP のテスト環境や ngrok での確認時に再現する。polyfill を最初から入れるべきだった
- split storage の残留問題は「完了時のクリーンアップ」を実装から漏らしていた設計ミス。localStorage への書き込み箇所を作る際に、削除タイミングも同時に設計する必要がある

## 学んだこと
- localStorage に複数の split 関連キーを保存する場合、完了イベントで一括クリアする cleanup 関数をユーティリティとして切り出すと漏れが防げる
- equal split のフェッチループは polling を使っている場合に「成功しても止まらない」バグが起きやすい。cleanup（`clearInterval`）の呼び出しタイミングを確認する

## 備忘
- `9eb57b3` の UUID fallback は `Math.random()` ベースなのでセキュリティ強度は低い。本番では必ず HTTPS を使う前提
- マップのデバッグログ削除（`b777e73`）はリリース前の必須クリーンアップだった
