## なぜ逸れたか
- V1 導線を修正するため ReservationsTab の動作を確認していると、render body で mutation（副作用）が走っていることに気づいた
- render-time mutation を修正する過程で「キャンセル済み予約が snapshot から復元されてしまう」ケースが露出した

## 反省
- `NEXT_PUBLIC_ENABLE_V2` を server-side API ルートと client-side コンポーネントの両方で参照していたが、Next.js では `NEXT_PUBLIC_` の扱いが build-time と runtime で異なる。環境変数の適用スコープを最初から明確にすべきだった
- render body での mutation（`updateReservationStatus` の呼び出し）は React の基本違反。コードレビューで防げた問題
- 0円席確保料のケースは設計段階で Stripe を呼ばないパスを用意すべきだった

## 学んだこと
- `NEXT_PUBLIC_` 環境変数は build 時に埋め込まれる。server-side の `process.env.NEXT_PUBLIC_*` と client-side の値が異なる場合がある（特に ISR/SSR）
- ReservationsTab のような一覧コンポーネントで render-time に外部状態を変更するのは React 原則違反。useEffect に移す
- コンポーネント分割（extract）は機能実装後に行うことで、大きすぎるコンポーネントの技術的負債を返済できる
