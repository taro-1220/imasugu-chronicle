## 最初にやろうとしてたこと

## 実際にやったこと
- コア読み取りパスを Supabase に移行（P5-5R-A）
- 予約ルートを Supabase に移行（P5-5R-B）
- Turso client と libsql 依存を完全削除（P5-5R-G）
- business ダッシュボードの読み取りパスを全て API 経由に変更（P5-6R-A）
- dailySales localStorage 依存を削除（P5-6R-F）
- business クーポン利用読み取りを API 化（P5-6R-G）

## 横道に逸れたこと
- business ダッシュボードの localStorage 依存が想定より広く、P5-6R-A〜G で複数 API を追加することになった

## なぜ逸れたか
- Turso 撤去は「クライアント削除」だけで済むと思っていたが、business ダッシュボードが localStorage 経由で間接的に Turso 同期データを使っていた
- localStorage の業務系フォールバックを全て遮断するために API 化が必要になった

## 反省
- localStorage が「Turso からの同期バッファ」として機能していたことを見落としていた
- 「libsql 削除→ビルドエラー」ではなく「読み取りパスを全て置換してから削除」の順番が正しかった

## 学んだこと
- 大規模 DB 移行は「write 移行 → read 移行 → 依存削除」の順番を守る
- localStorage を中間バッファにしていると、DB 移行の影響範囲が見えにくい

## 備忘
