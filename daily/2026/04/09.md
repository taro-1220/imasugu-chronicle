## 最初にやろうとしてたこと
- 料金モデルを一本化して UI 文言を整合させる

## 実際にやったこと
- 事業者ログイン認証を localStorage 管理から JWT Cookie セッションへ移行
- ログインの rate limiting・input validation・unified error format・logging を追加
- getClientIp ヘルパーを抽出（x-forwarded-for 対応）
- 料金モデルを一本化・UI 文言整合・他店舗非表示

## 横道に逸れたこと
- 「料金モデル整合」のつもりで作業を始めたが、事業者認証が localStorage ベースの設計になっており
  セキュリティ問題として先に対処することになった
- 認証移行に伴い、認証関連コードをほぼ全面的に書き直す必要があった
- rate limiting / input validation はセキュリティ監査の結果として同日追加になった

## なぜ逸れたか
- localStorage に認証状態を保持する設計は XSS に対して脆弱で、
  複数タブ・リロードで状態が揺れる。本番化に向けて先に解消すべきと判断した
- JWT Cookie への移行は「認証状態が信頼できる場所に保存される」という根本的な設計変更で、
  既存の認証関連コードに広く波及した

## 反省
- 認証設計を最初から JWT Cookie にしておけば、全面書き直しのコストは不要だった
- localStorage への認証保存は開発初期の暫定対応のまま放置していた。
  本番化判断のタイミングで一気に負債回収になった

## 学んだこと
- 事業者（管理者）の認証状態は localStorage ではなく HttpOnly Cookie に保存する
- rate limiting は IP 単位で入れる。x-forwarded-for の扱いは Vercel 環境では注意が必要
- getClientIp を共通ヘルパーにしておくと、ミドルウェア・API ルートで再利用できる

## 備忘
- JWT の有効期限と refresh 戦略を確認する（セッション切れ時の UX を確認）
- rate limiting のしきい値が適切かどうか実運用で確認する
