## 最初にやろうとしてたこと
- restaurantId を全型に適用してテナント分離を強化する

## 実際にやったこと
- restaurantId を全テナント依存型・ストアに強制付与
- restaurant スコープの localStorage キー体系に全面移行
- payment-confirm ステップを新設（保存済みカードでの誤予約防止 UX）
- storeId を sequence で自動付与する仕組みを追加
- PublicSlot に storeId を追加して React key 衝突を修正
- order/visit/billing/coupon の transaction key chain を修復
- coupon の restaurant_id フォールバックを復元（401 ブロック解消）
- businessRestaurants を ownerLoginId でキー付けしてテナント混在を防止

## 横道に逸れたこと
- transaction key chain が切れて order→visit→billing→coupon の連鎖が壊れた
- coupon が 401 を返す問題が発生し、restaurant_id フォールバック復元へ対処
- React key 衝突で PublicSlot の描画が崩れ storeId 追加が必要になった

## なぜ逸れたか
- localStorage のグローバルキーをスコープ付きキーに一括変換したため、既存のキー参照が軒並み不一致になった
- restaurantId をカスケードで型に追加したことで未対処箇所が多数露見した

## 反省
- スコープ付きキー移行は一括ではなく書き込み→読み取りの順に段階移行すべきだった
- payment-confirm は同日追加・3日後に削除されることになり、設計検討が不十分だった

## 学んだこと
- localStorage キーのスコープ変更はトランザクション連鎖全体を把握してから行う
- グローバルキーからスコープ付きキーへの移行は「二重書き込み期間」を設けるのが安全

## 備忘
- login と session restore で restaurant_id が null の場合はブロックするよう変更した
- payment-confirm は UX の邪魔として後日削除予定（この時点では未確認）
